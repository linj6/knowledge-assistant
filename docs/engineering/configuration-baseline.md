# V1 初始配置基线

日期：2026-11-07；适用范围：V1 P0。本文将 [M0-07 设计](m0-07-test-design.md) 的六类候选值确认为工程初始基线，不是性能最优结论或容量承诺，不改变产品范围与架构决策。不新增尚未使用的 Spring 配置属性。

## 初始值、边界与验证责任

以下为最初规划基线；Worker 的当前实现状态已于 M1-12 更新如下，其他条目的历史描述不代表当前逐项验收结论。已实现的 TokenEstimator 不表示 RAG 预算已经实现。

| 类别 | 初始值、单位与含义 | 约束边界 | 计划实现阶段与验证方式 |
|---|---|---|---|
| 上传大小 | 单文件最大 10 MiB（10,485,760 字节）；单次请求总量建议 12 MiB（12,582,912 字节），为 multipart 开销留余量 | 单文件与请求限制分别校验；请求总量不能替代文件大小限制，网关、Servlet 与业务校验需一致 | M1-03：空文件、恰好上限、超 1 字节、多文件请求及解码内存验证 |
| 知识库文档数 | 每知识库最多 1000 个非删除文档，单位为文档个数 | 并发写入需要原子容量判断；删除和处理中状态的计数口径待确认 | M1-01/03 定义并实现计数；M1-13、M2 验证并发创建、删除及发布集合枚举 |
| ES terms | 单次 terms 查询应用层最多 2000 个唯一版本 ID，去重后计数 | 同时遵守实际索引 index.max_terms_count，实际有效上限取两者较小值；不得假定常见默认值就是目标索引实值 | M2-01/03：读取目标索引设置，验证重复 ID、边界、越界和较低索引上限；禁止静默截断掩盖越界 |
| Worker 重试 | 最多重试 3 次，连首次共 4 次；退避 5/15/45 秒，每次 ±20% 抖动 | 对应延迟区间为 4–6、12–18、36–54 秒；需避免与客户端重试叠加放大调用次数 | M1-08/12/13：持久化次数、错误分类、退避范围、崩溃恢复与次数耗尽验证 |
| Worker 租约与时限 | 任务租约15分钟，最大执行时间10分钟，协作式超时，不自动续租 | 执行时间必须小于租约，恢复只处理过期且不同owner的RUNNING；单Worker部署约束不变 | M1-12实现，验证见本节末尾验收链接 |
| RAG 预算 | 证据预算 4096 估算 tokens；初始回答预留 1024 tokens | 另计系统提示词、用户问题及协议开销，输入与回答合计受实际模型上下文窗口约束；窗口不足时不能机械采用这两个值 | M3-01/02/06：长中文、混合文本、超长问题、窗口边界与真实 usage 校准，验证预算不足处理 |

## 已实现与已验证的边界

现有 ModelProperties、RerankProperties 和 application.yml 已实现模型默认关闭及 30 秒调用超时配置；数据源与 Flyway 配置已存在。它们不是 Worker 租约、任务时限或重试配置；Worker 现状以本文 M1-12 修订节为准。Compose 的端口、健康检查重试也不是业务参数。

TokenEstimator 已实现估算并返回 exact=false，现有固定开销和默认 20% 余量未经充分校准，不能称为精确 token 数，也不保证不低估。模型历史接入与离线测试证据见 [模型报告](model-capability-report.md)，不构成上述预算正确性的验证。其他类别的业务边界、性能与故障行为仍待相应阶段验证；Worker 本轮测试见 M1-12 验收，未执行模型请求。

## 待业务阶段确认的问题

- M1：非删除文档如何映射具体状态，处理中、失败、删除中和并发创建如何计数；请求总量的 multipart 口径及是否支持多文件，由上传接口任务确认，不据 12 MiB 推导新的批量上传规则。
- M1-12 已明确错误分类、执行次数及截止时间；客户端超时和各阶段检查、完整导入故障恢复由 M1-13 验证。
- M1/M2：非删除文档与发布版本集合的对应关系、实际索引上限的读取时机、越界错误协议需确认；1000 个文档不能直接证明所有查询版本集合均小于 2000。
- M3：模型窗口、回答输出上限、估算校准与预算不足时的处理策略需确认；1024 是初始回答预留，不是当前已生效的模型输出配置。

M0 状态与剩余验收缺口见 [验收报告](m0-verification-report.md)。后续调整应记录原因和验证证据，不把初始假设写成实测结论。

## Embedding V1 冻结基线（2026-11-08 归档）

依据操作者 2026-11-07 的四次真实在线请求，冻结以下参数；完整证据及验证边界见 [Embedding 基线验证](embedding-baseline-verification.md)。

| 参数 | V1 基线 |
|---|---|
| Provider | DashScope |
| Model | text-embedding-v4 |
| Dimension | 1024 |
| Encoding | float |
| Distance | cosine |
| Endpoint | https://dashscope.aliyuncs.com/compatible-mode/v1 |
| SDK maxRetries | 0 |

文档与查询向量必须使用兼容的 Embedding 空间；V1 使用同一模型及参数，不能仅凭维度相同认定兼容。cosine 属于向量检索配置，不是 Embedding API 参数；数据库及检索实现留待后续授权任务。

离线审阅确认：classpath application-local.yml 的端点、模型和维度与基线一致；ModelConfiguration 显式设置 float 和 maxRetries=0，无需配置或代码修复。未读取私有 config/application-local.yml，个人覆盖及环境变量的实际生效值未验证；部署与运行时仍须遵守冻结基线。通用超时保持 30 秒，独立在线基线测试使用 20 秒。

本次仅解除 Embedding API 基线前置阻断，不代表 M1-01、向量检索或 RAG 质量验收通过。

## M1-12 单 Worker 运行基线

M1-12 替代 M1-09 的120秒租约现状及历史续租规划。统一由 WorkerProperties 绑定 assistant.worker，启动校验，即使开关关闭也拒绝非法参数。未注册生产 TaskProcessor；开关开启但无处理器仍不领取。恢复随任务扫描执行；存储清理由MinIO ILM和即时补偿负责，与Worker开关无关。

| 配置 | 默认值 | 约束与含义 |
|---|---|---|
| enabled | false | 默认关闭任务扫描 |
| scan-interval | 5s | 正数，固定延迟 |
| batch-size | 1 | 1～10，顺序执行 |
| lease-duration | 15m | PG statement_timestamp() 加配置时长 |
| max-task-duration | 10m | 正数且小于租约；从开始执行算起，不含排队和退避 |
| max-attempts | 4 | 大于0；attempt_count 是已开始执行的总次数 |
| retry-backoff | [5s, 15s, 45s] | 正数，数量等于 max-attempts−1 |
| retry-jitter | 0.2 | 有限数，0～1；默认±20%，区间4～6/12～18/36～54秒 |

所有时长均为整毫秒，范围为1毫秒至365天。失败只保存固定安全码及描述，未知 RuntimeException 不自动重试。过期任务仅恢复不同 owner，未耗尽次数时安排同一退避策略；恢复本身不递增执行次数，重新领取递增 attempt_count 和 claim_epoch。

不自动续租、不强制终止线程、不提供跨进程 fencing。部署必须保证单 Worker，重启前确认旧执行进程已停止。上传在同一Bucket中使用唯一 staging/ 和 originals/ Key，服务端复制后短PG事务只保存正式Key；PG异常先查引用再补偿，查询失败保留并告警。staging/ 的原生ILM过期天数为2，不在应用配置Worker扫描参数；原三个orphan扫描参数已删除。规则部署、检查及历史正式对象人工核对见 [MinIO部署](../../infra/minio/README.md)。

实际验证与未验证边界见 [M1-12 验收](m1-12-verification.md)。M1-12 不接入真实导入链路，完整 E2E 留待 M1-13。
存储现状以 [M1-12存储简化](m1-12-storage-simplification.md) 为准；不再提供应用层定时扫描。
