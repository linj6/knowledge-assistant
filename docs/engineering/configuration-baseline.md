# V1 初始配置基线

日期：2026-11-07；适用范围：V1 P0。本文将 [M0-07 设计](m0-07-test-design.md) 的六类候选值确认为工程初始基线，不是性能最优结论或容量承诺，不改变产品范围与架构决策。不新增尚未使用的 Spring 配置属性。

## 初始值、边界与验证责任

以下为最初规划基线；Worker 的当前实现状态已于 M1-09 更新如下，其他条目的历史描述不代表当前逐项验收结论。已实现的 TokenEstimator 不表示 RAG 预算已经实现。

| 类别 | 初始值、单位与含义 | 约束边界 | 计划实现阶段与验证方式 |
|---|---|---|---|
| 上传大小 | 单文件最大 10 MiB（10,485,760 字节）；单次请求总量建议 12 MiB（12,582,912 字节），为 multipart 开销留余量 | 单文件与请求限制分别校验；请求总量不能替代文件大小限制，网关、Servlet 与业务校验需一致 | M1-03：空文件、恰好上限、超 1 字节、多文件请求及解码内存验证 |
| 知识库文档数 | 每知识库最多 1000 个非删除文档，单位为文档个数 | 并发写入需要原子容量判断；删除和处理中状态的计数口径待确认 | M1-01/03 定义并实现计数；M1-13、M2 验证并发创建、删除及发布集合枚举 |
| ES terms | 单次 terms 查询应用层最多 2000 个唯一版本 ID，去重后计数 | 同时遵守实际索引 index.max_terms_count，实际有效上限取两者较小值；不得假定常见默认值就是目标索引实值 | M2-01/03：读取目标索引设置，验证重复 ID、边界、越界和较低索引上限；禁止静默截断掩盖越界 |
| Worker 重试 | 最多重试 3 次，连首次共 4 次；退避 5/15/45 秒，每次 ±20% 抖动 | 对应延迟区间为 4–6、12–18、36–54 秒；需避免与客户端重试叠加放大调用次数 | M1-08/12/13：持久化次数、错误分类、退避范围、崩溃恢复与次数耗尽验证 |
| Worker 租约与时限 | 现有 SQL 领取租约120秒已生效；每30秒续租、最长10分钟仅为历史规划，未实现 | 失败更新要求未过期租约；没有续租、执行时限或过期接管。单 Worker 不保证跨进程互斥 | M1-09确认边界；M1-12在正式执行前解决超时与基本恢复；M1-13验证单 Worker 常见故障，不要求完整续租/fencing |
| RAG 预算 | 证据预算 4096 估算 tokens；初始回答预留 1024 tokens | 另计系统提示词、用户问题及协议开销，输入与回答合计受实际模型上下文窗口约束；窗口不足时不能机械采用这两个值 | M3-01/02/06：长中文、混合文本、超长问题、窗口边界与真实 usage 校准，验证预算不足处理 |

## 已实现与已验证的边界

现有 ModelProperties、RerankProperties 和 application.yml 已实现模型默认关闭及 30 秒调用超时配置；数据源与 Flyway 配置已存在。它们不是 Worker 租约、任务时限或重试配置；Worker 现状以本文 M1-09 修订节为准。Compose 的端口、健康检查重试也不是业务参数。

TokenEstimator 已实现估算并返回 exact=false，现有固定开销和默认 20% 余量未经充分校准，不能称为精确 token 数，也不保证不低估。模型历史接入与离线测试证据见 [模型报告](model-capability-report.md)，不构成上述预算正确性的验证。六类参数的业务边界、性能与故障行为均待相应阶段验证；本轮没有运行测试或模型请求。

## 待业务阶段确认的问题

- M1：非删除文档如何映射具体状态，处理中、失败、删除中和并发创建如何计数；请求总量的 multipart 口径及是否支持多文件，由上传接口任务确认，不据 12 MiB 推导新的批量上传规则。
- M1：哪些错误可重试，崩溃/重新领取是否消耗次数；10 分钟从何时起算、是否包含排队和退避、超时如何取消与恢复，需随状态机确认，不在本文发明规则。
- M1/M2：非删除文档与发布版本集合的对应关系、实际索引上限的读取时机、越界错误协议需确认；1000 个文档不能直接证明所有查询版本集合均小于 2000。
- M3：模型窗口、回答输出上限、估算校准与预算不足时的处理策略需确认；1024 是初始回答预留，不是当前已生效的模型输出配置。

M0 状态与剩余验收缺口见 [验收报告](m0-verification-report.md)。后续调整应记录原因和验证证据，不把初始假设写成实测结论。

## Embedding V1 冻结基线（2026-11-08 归档）

依据操作者 2026-11-07 的四次真实在线请求，冻结以下参数；完整证据及验证边界见 [Embedding 基线验证](embedding-baseline-verification.md)。

| 参数 | V1 基线 |
|---|---|
| Provider | DashScope |
| Model | text-embedding-v4 |
| Dimension | 1024 |
| Encoding | float |
| Distance | cosine |
| Endpoint | https://dashscope.aliyuncs.com/compatible-mode/v1 |
| SDK maxRetries | 0 |

文档与查询向量必须使用兼容的 Embedding 空间；V1 使用同一模型及参数，不能仅凭维度相同认定兼容。cosine 属于向量检索配置，不是 Embedding API 参数；数据库及检索实现留待后续授权任务。

离线审阅确认：classpath application-local.yml 的端点、模型和维度与基线一致；ModelConfiguration 显式设置 float 和 maxRetries=0，无需配置或代码修复。未读取私有 config/application-local.yml，个人覆盖及环境变量的实际生效值未验证；部署与运行时仍须遵守冻结基线。通用超时保持 30 秒，独立在线基线测试使用 20 秒。

本次仅解除 Embedding API 基线前置阻断，不代表 M1-01、向量检索或 RAG 质量验收通过。

## M1-09 单 Worker 运行基线修订

V1 采用单 Worker，Spring Scheduling 保留；不建设完整分布式 fencing 或自动续租。`assistant.worker.enabled=false` 默认关闭，扫描固定延迟默认5秒，每轮默认1项、允许1～10项，顺序执行；没有生产 TaskProcessor 时即使开启也不领取。以上是现有代码行为，不代表自动导入已完成。

TaskMapper.xml 使用 PostgreSQL statement_timestamp() 设置 lease_until 为领取时刻加120秒，同时递增 attempt_count、claim_epoch。失败更新核对 lease_owner、claim_epoch、RUNNING 和未过期租约；超过120秒的处理器异常不能通过该入口标记 FAILED，任务仍可能停在 RUNNING。处理器正常返回也保持 RUNNING，不标记成功。没有续租、过期任务自动接管，也没有10分钟强制执行上限；现有模型30秒调用超时不是任务整体超时。

正式 Worker 上线前，M1-12 必须明确单任务超时、终止确认、失败状态收敛及重启恢复办法，并解决120秒约束对长任务的影响；本次不调整既有参数，不将历史30秒续租/10分钟上限作为已生效配置或 M1-09 必需交付。恢复前确认原执行者停止，不能因租约到期直接启动重叠导入。部署必须只运行一个导入 Worker；租约字段和开关不是跨进程互斥保证。

历史 M1-08 验证记录及代码注释中的后续 fencing/续租规划，由本次 [M1-09 决策](m1-09-verification.md)取代，保留历史记录和现有安全校验，不删除字段或修改迁移。
