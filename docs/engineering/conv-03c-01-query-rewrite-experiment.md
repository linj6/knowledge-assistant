## 冻结和 A/B 协议

1. 计划复用 M4 LIVE 记录中的 KB `800000` 与 `FIXED_CODE_POINT` 发布索引。执行前只读确认这个环境中实际的 KB、文档内容 SHA、发布版本映射、切分和 snapshotHash。A/B 固定同一份已核验快照、同一查询 Embedding 模型和索引配置。快照变化时该批次失效，另行登记。
2. 固定 `HYBRID_RRF` 及 `RetrievalParameters(20, 20, 60, 20, 5)`，依次为 vectorTopK、bm25TopK、rrfK、fusionTopK、finalTopK。A 和 B 各调用一次相同的 `RetrievalService.search`，相同文本也分别执行两臂。跨样本按固定 caseId 顺序，奇数先 A、偶数先 B。记录请求和实际策略，降级结果单列且排除有效配对。
3. 检索前先按固定历史调用 QueryRewriter。保留 `REWRITTEN`、`UNCHANGED`、`FALLBACK`、`SKIPPED`；只有 `REWRITTEN` 的 B 使用模型改写，其余状态使用原问题。记录模型、Prompt 版本、每题输入和生效 Query 的 SHA-256，以及审阅者和结论。人工在查看检索结果前检查指代、限定条件、话题切换和是否增加或删减要求。冻结原始输出对应的生效 Query 与审阅结论；发现意图偏移时登记失败，仍按冻结 Query 执行已授权检索并单列结果，不手改或重生成。
4. 主报告使用同一批双方均可评分的配对，保留意图偏移个案以体现端到端效果，另列意图忠实子集和各改写状态。按题报告 A、B、B−A，给出宏平均和有效分母。正常空结果贡献零命中；检索失败、缺失、快照／证据映射不符分别记录原因并排除配对。零有效配对时指标为空。
5. Recall@5 是 Top-5 完整覆盖的 Gold 条数除以该题必要证据条数。MRR@5 用首次完整覆盖任一 Gold 的前缀排名倒数，未命中为零。Evidence Coverage 使用 M4 Complete Evidence Coverage@5，全部必要证据完整覆盖计 1，否则计 0，并报告 covered/total。只有同一来源版本上的区间并集完整覆盖才命中。
6. nDCG@5 当前为 **NOT READY**。如后续授权人工标注，另建每题 A/B Top-5 并集评审池，以同一切分下的文档、发布版本、Chunk 身份去重，隐藏臂别、排名和检索分数。按 M4 的人工 0–3 级口径评完后才用该池计算 IDCG，未评保持 NOT READY，全零池记 UNDEFINED。M4 历史标签不移植到该池。

## 复用与记录

- 复用 [M4 指标协议](m4-b01-retrieval-metrics-protocol.md) 和测试侧 `EvidenceMetrics.calculate`、`FrozenRankingEvaluation.mean`。若新池人工标签齐备，复用 `RankingMetrics.calculate`。按 C02 的 Chunk 正文、版本和区间核验原则校验候选后，将两臂结果适配到同一 caseId 的 Gold。分别保存意图基线与执行 Query 指纹。
- [C01 Offline Runner](m4-c01-offline-runner.md) 回放冻结结果，[C02 Live Runner](m4-c02-live-runner.md) 固定读取 M4 的 12 个原问题，按原 Query SHA 判断评分资格。因此本实验后续用轻量测试侧入口或一次性调用连接现有 QueryRewriter、RetrievalService 和指标函数。沿用 C02 的只读和费用门禁、快照／来源校验及输出指纹约定，使用独立产物目录。现有 Runner、冻结问题、Gold、评审池、历史结果均保持原样。
- 每题记录 `rewriteElapsedMs`、`retrievalElapsedMsA/B`、`rewriteModelCalls`、`embeddingCallsA/B`、状态、可确认的失败类别和是否原问题回退。另记录实际输入、输出及总 Token（模型响应可提供时），缺失填 null。当前 QueryRewriter.Result 仅有 Query 和状态，后续只从测试侧可获得的模型响应元数据记录 Usage；无法识别具体失败类别时也填 null。
- 区分服务阶段耗时与端到端新增耗时。A 总耗时取原问题检索路径的墙钟耗时；B 总耗时取逐题改写和改写后检索两段的墙钟耗时及可测接入开销；两者差作为整体新增耗时。分批冻结时标记 B 为分阶段合计，排除人工审阅和批次等待。分别报告改写耗时、检索差值和总差值。

## 后续授权

完整执行需明确授权只读访问目标 KB／发布快照、指定改写 Chat 模型及供应商（最多 10 次请求）、匹配发布索引的在线查询 Embedding（最多 20 次，两臂各 10 次），并在运行前确认供应商、模型、费用上限及失败处理。零额外重试。改写和检索分别授权，前者完成与审阅冻结后才开始后者。费用仅按实际请求及供应商 Usage 核对。答案生成、Rerank、索引构建、数据写入均不属于该实验。当前发布快照与线上访问条件待确认，本轮没有执行模型、Embedding 或检索，也没有产生实验费用或指标结果。
