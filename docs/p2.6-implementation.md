# P2.6 本地 Git 知识接入实施计划

在 `feature/p2.6-knowledge-source` 上依次完成 GIT-01 → GIT-02 → GIT-03 → GIT-04。以 `backend-interview-lab` 的 Spring 事务专题和相关面试复盘验证从已提交文档到多轮问答、引用核对的完整流程。

## 已确认的实施边界

- 保持单 Maven 模块和单体 Spring Boot。使用 Git CLI 与 `ProcessBuilder`，服务端配置仓库和授权账号，功能默认关闭。应用读取当前 HEAD 的已提交内容。浏览开始固定 Commit SHA，选择、预览、提交及读取重试均基于该提交。
- 支持普通 `.md` 文件和目录递归多选，提交前可调整清单。单批默认最多 30 个文件，单文件沿用 2 MiB 上限。保留仓库、分支、相对路径、SHA 及可选 GitHub 版本链接。本地提交可能尚未推送。
- 同库相同正文复用已有文档和任务，并关联新增来源。同一来源正文变化时提示并跳过。沿用单文件异步导入、切分、Embedding、发布和索引重试。
- 本期暂缓应用内 Git Pull、分支切换、自动同步、Webhook、文档版本替换、GitHub API 与凭据接入、MCP、通用数据源框架、学习业务模块和 Agent。

## GIT-01 本地仓库接入与浏览

**目标**　授权账号可以浏览允许访问的本地 Git 仓库，获得绑定固定提交的 Markdown 清单。

**范围与代码**　在 `ingestion.git` 增加配置、Git 命令执行、仓库读取、内存快照及仓库列表、快照创建、目录浏览和清单预览接口。使用提交树和 blob 读取普通文件，校验配置仓库根目录，跳过符号链接和子模块。快照绑定账号和仓库，设有效期和数量上限。命令使用独立参数，限制执行时间及输出，禁用交互和按需拉取。

**必要测试**　用临时 Git 仓库覆盖授权、中文及空格路径、递归去重、数量和大小边界、快照过期、未提交修改及 HEAD 移动后的固定提交读取。覆盖 Git 不可用和超时处理。

**验收**　应用进程能从配置的仓库浏览并读取指定提交。关闭功能或账号未授权时，仓库入口不可用。请求无法指定任意服务器路径或读取任意提交。

## GIT-02 持久化与导入链路集成

**目标**　单个 Git 文件能够通过现有导入生命周期入库，来源、文档、任务及明细回执保持一致。

**范围与代码**　新增 Flyway 迁移，创建 `document_git_source`、`git_import_batch`、`git_import_batch_item`。来源按知识库、仓库键、分支标识和路径唯一。批次保存原始 `snapshotId`、固定 SHA、请求 ID 和确认清单，同库请求 ID 唯一，批次内路径唯一。为 `DocumentImportService` 增加可信字节入口，保留 Multipart 入口并共用校验与入库。复用知识库行锁和两次短事务，最终加锁后重判来源、内容和预期明细 `revision`，同事务提交来源与回执。Git 与 MinIO 操作在事务外，沿用对象补偿。文档删除事务清理来源关联，历史批次保留；已删除知识库的批次不可访问。

**必要测试**　验证迁移和唯一约束、同内容多来源、同来源变更跳过、容量已满时复用、并发同来源不同正文、迟到明细回写、对象补偿、删除后重新导入，以及 Multipart 回归。

**验收**　新建和复用均关联正确来源及任务，并发下每个明细版本只接受一次结果。现有 Worker 可从已保存原文完成发布或重试。

## GIT-03 批量 API 与前端交互

**目标**　用户在知识库文档页确认一批文件，跟踪结果，并在刷新或离开后继续未提交项。

**范围与代码**　实现批次创建、最近批次、详情及逐文件提交 API。批次创建按请求 ID、原始快照 ID 和持久化清单做幂等校验，快照过期后仍可找回已创建批次。逐文件请求携带预期 `revision`。在现有 Vue 3、TypeScript 和 Element Plus 页面加入单一导入弹窗及文档详情来源展示。页面顺序提交，离开后停止发送剩余请求。提交阶段失败按原 SHA 逐项重试，索引失败复用现有任务重试。沿用请求封装、状态文案与轮询交互。

**必要测试**　覆盖批次权限、过期快照后的幂等重提、不同清单冲突、旧 revision 重传、部分失败和恢复、文档删除后的历史回执。运行现有前端构建及类型检查，手工检查弹窗和继续提交。

**验收**　清单可预览和调整。最近批次能恢复原进度，已创建任务照常执行。文件提交进度按路径计数，发布进度仅统计本批新建的唯一任务。复用项单独显示文档当前状态，来源变化明确标为跳过。关闭功能或未授权时隐藏入口，已有来源仍按文档归属展示。

## GIT-04 工程验收与真实使用验证

**目标**　分别记录工程回归结果和实际技术学习效果。

**范围与代码**　补齐 IDEA 本地配置和 Docker 部署说明。Docker 运行环境提供 Git，授权仓库连同 `.git` 只读挂载，验证实际运行 UID 的读取权限。仅修复验收发现的本期问题。

**必要测试**　执行阶段完整回归及前端构建，验证 IDEA 和 Docker 路径、授权、部分失败、继续提交、内容复用、来源变化及删除。真实模型请求须获得用户明确授权，Docker 启动须在任务授权范围内。

**验收**

- **工程报告**记录实际执行范围、命令、结果及未验证事项。日志可用批次和明细 ID、仓库键、相对路径、SHA、失败阶段、耗时、退出码和任务 ID 定位问题，正文和凭据不进入日志。
- **真实使用报告**记录实际仓库提交和导入文件清单。将 Spring 事务专题和相关面试复盘从本地仓库批量导入并发布，在同一知识库会话中做多轮技术问答。逐条核对关键回答引用的文档、段落和提交版本，记录追问是否延续上下文、证据是否支撑回答及学习体验中的问题。若结果不理想，保留具体问题作为后续迭代依据。

各开发任务只执行影响范围内的验证。任务提示词引用本文和 [代码风格](code-style.md)、[包结构](package-structure.md)，只附对应任务、前置结果及当次验证范围。计划确认后直接开始 GIT-01。
